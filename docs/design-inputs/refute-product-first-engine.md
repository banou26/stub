# Refutation: proposal-product-first, through the engine and contracts lens

Scope: every Cypher statement against `00`; the ingest against `04 section 1`; the five reads against
`04 section 2` and `02 section 4`; the plugin contract; the test plan against `04 section 5`; the
migration steps. Code checked directly where a contract turned on it.

Verdicts: **HOLDS** (the design already satisfies it), **FIXABLE** (wrong or missing, repairable
inside the design), **FATAL** (cannot be satisfied without changing a stated principle).

---

## (d) The plugin contract

| # | item | verdict | evidence | what would fix it |
| --- | --- | --- | --- | --- |
| D1 | **whole-output diff and delta scoping cannot both hold** | **FATAL** | `5.1`: `run` must "Compute the plugin's WHOLE desired output from the graph", and the writer "diffs it against what this plugin wrote last time (by = id) and applies the delta", with "A retract is an empty `desired`" (`5.2`). `5.1` also hands the plugin `delta` "so a scan can be scoped", and `5.4` uses it: `P1`'s scan is "scoped to `delta.claims` on an incremental pass", `P3`'s is "scoped to clusters with a changed profile on an incremental pass". A scoped run returns a PARTIAL desired set, so the writer deletes every `LINK` that plugin wrote for anything outside the delta. On the second flush of any session, `plugin:title` and `plugin:range` retract nearly all of their own output, then re-mint it on a later full pass, and the graph oscillates every 50 ms. Both repairs cost a principle: recompute fully every pass and the cost budget of `11.1` cannot hold (`P3`'s pairwise wasm loop is today's whole fuzzy pass, `02 section 2.10`, now run up to four times per flush instead of once per 100 ms debounce); or scope the diff and "idempotent by construction", which is what `5.3`, `9.3` and `11.3 I1` all rest on, stops being a property of the contract and becomes a property each plugin has to be trusted to have | make the scope explicit and part of the output: `run` returns `{scope: <the keys it recomputed>, output}` and the writer diffs ONLY within that scope, with a rule for an edge whose endpoints straddle the boundary. Then state idempotency as "same graph, same scope, same output", and have `runPlugin` assert it that way |
| D2 | the core cannot prove a plugin left a source row alone | FIXABLE | `5.3` offers three proofs. (1) is a TypeScript type, erased at runtime, plus validation of the rows a plugin RETURNS, which is not where an accidental write would come from. (2) is a string checker for `CREATE, MERGE, SET, DELETE, DROP, COPY, ALTER` "outside string literals": `00` records that multi statement `query("...; ...")` works, the list omits `CALL`, `ATTACH`, `LOAD`, `IMPORT`, `EXPORT`, `DETACH` and `REMOVE`, and nothing is said about comments, so the checker is a parser problem solved with a word list. (3) is the only runtime proof and it is `max(m.seq), count(m)` per table: a `SET m.scope = 'RUN'` on an existing row moves neither, and `scope` is precisely the column a profile plugin would be tempted to write | run `ctx.query` on a connection opened read only if the engine offers one; otherwise hash the source tables in production the way `9.3` already hashes them in the harness, and compare per pass. The hash is the proof; the other two are ergonomics |
| D3 | two plugins disagreeing is only guarded in one direction, and only at proposal time | FIXABLE | Guard 6 refuses a `SAME_AS` when an active `PART_OF` or `INCLUDES` already joins the pair (`3.5`, `5.2`). Nothing refuses the reverse: `partOf`'s guards are only `unknown-scope`, `self`, `inverted` (`5.2`). So `plugin:title` welds a pair in pass N, a later kitsu `asserted` claim arrives and `plugin:direct` writes `PART_OF` over the same pair in pass N+1, both are active, and the `SAME_AS`-only closure of `3.5` merges them. The owner's rule is then broken by arrival order, which is the one thing `G3` promises cannot happen | evaluate the containment rule as a post-pass invariant over the whole graph (it is one query) and retract the weaker edge by a declared precedence, not by which plugin ran first |
| D4 | a plugin that throws mid-run is unspecified | FIXABLE | Nothing in `5.1`, `5.2` or `5.3` says what happens. The writer has already applied earlier plugins' deltas, so the graph is half updated; if the pass aborts, `view:changed` does not fire, and `04 section 3` states the consequence: "An event that does not fire leaves a page empty forever" | per-plugin try/catch: a throwing plugin keeps its PREVIOUS output (never an empty desired set, which would retract everything it ever wrote), the pass continues, `view:changed` still fires for what did run, and the failure is a `Cluster.anomalies` entry so it is visible in the same place as every other contradiction |
| D5 | ordering, cycles and the four-iteration cap | FIXABLE (minor) | `5.3`: "Cycles are legal; the pass iterates to a fixed point ... capped at four iterations per emit with a warning". A capped pass is by definition not a fixed point, and reads run against whatever state the cap left, so `G3` ("the same graph renders the same page") holds only between quiet periods. `11.1` argues the residue converges on the next flush, which is true and is not the same claim | qualify `G3`: the same graph renders the same page AT A FIXED POINT, and make the cap a logged anomaly rather than a warning, so a graph that keeps hitting it is visible |
| D6 | retraction and recompute are idempotent everywhere except the one place with state | FIXABLE | `5.3`'s full pass is genuinely reversible for `direct`, `title`, `range`, `containment` and `profile`. `plugin:aggregate` carries `Cluster.id` across passes through `ctx.previous`, and retracting it deletes exactly that state, so disable-and-re-enable is NOT identity for the ids the app caches on. Same defect as C5 | as C5: hold the id assignment in a table the aggregate may write but not retract |
| D7 | the guards are one chokepoint and the refusals are stored | HOLDS | `5.2` puts every `SAME_AS` from every source (handle, `similarMedia` answer, title match) through one guard list, which is what `01 case 2` and `01 case 7` ask for and what today's three pair linkers plus the scope dispatch plus the resolver comment cannot do (`02 section 3` items 4 and 5). Storing a refusal as `LINK {status:'refused', reason}` makes `01 case 6` a query instead of four silent short circuits | |
| D8 | episode identity per proven pair rather than per offset | HOLDS | `3.4` and `P4` rule 1 place a button only from an `EPISODE_LINK` carrying the two days, which directly refutes the offset vote of `01 R1` and gives `01 case 15` its piecewise mapping with no vote anywhere. `6.4`'s slot read reaches a play button only through `FILLS`, which exists only because a member hung it or a pair proved it | |

## Summary

### Fatal

1. **The plugin writer's whole-output diff and the `delta` scoping contradict each other (D1).** `run`
   must return the WHOLE desired output and the writer applies `DELETE current - desired`, while
   `delta` exists "so a scan can be scoped" and `P1` and `P3` scope theirs. A scoped run therefore
   retracts every edge outside its scope on every incremental pass. Repairing it costs a principle in
   either direction: full recompute per 50 ms flush breaks the cost budget of `11.1` (`P3` is today's
   entire fuzzy pass, `02 section 2.10`, run up to four times per flush instead of once per 100 ms
   debounce), and a scoped diff removes "idempotent by construction", which `5.3`, `9.3` and `11.3 I1`
   all rest on.

### Serious

1. The `6.1` page query does not compile: `uri` is unbound inside the `EXISTS` subquery, and `00`
   records that a binder error THROWS (A1).
2. The anomaly trace query is unconditionally true: `size()` over a JSON column that `00` says reads
   back as a string, so `'[]'` passes (A6).
3. The generic plugin writer cannot write `MediaProfile.startDay` or `EpisodeProfile.day`: `00` says a
   STRING param into a DATE column is a binder error (A7).
4. `P2`'s span scan is a cartesian product with no join predicate between the run side and the folding
   side, expanded over episodes, run every pass, while `11.1` claims every plugin is delta scoped (A9).
5. `P0` scans the append-only `Answer` log on a non-key column while the `ABOUT` edge declared for that
   join is never used (A10).
6. The read budget is met in query count and missed in bytes: `6.1` returns every member's `raw`, which
   `00` says comes back as a string, and the card's fields (covers, descriptions, genres, tags,
   popularity, relations) are projected nowhere else (A11).
7. Ingest, up to four plugin iterations, every subscription read and seven blocking extractors all
   share `00`'s single-threaded engine lane, and no cost is ever summed over one 50 ms window (A12).
8. The "250 rows is well under 50 ms" argument reads `00`'s 2,000-in-107 ms number backwards, because
   the loader batches 250 TOP-LEVEL medias and `recursivelyUnwrapMediaHandles` flatMaps each first
   (`src/worker/extractor.ts:107`) (B2).
9. The ingest cannot compute the `changed` set it emits: `MERGE` reports no newness and step 2 reads
   only `Media`, so today's boolean guard (`graph.ts:293-296`) is replaced by a full six-plugin pass
   per flush (B3, B4).
10. The container badge the design is built around cannot be drawn: a PART_OF-only placeholder is in no
    `Cluster`, so `ATTACHED_TO` never reaches it, and `8.1` assumes the opposite (C1).
11. `I14` is claimed to hold and does not: a CONTAINER cluster has slots, so `mergeByEpisodeNumber`
    runs over `paramount`, `trakt` and `tvdb` rows that flatten every season, which is the precondition
    `db.ts:465-468` forbids (C2).
12. `exportStore` over raw `CLAIMS` re-admits every cross-scope SAME_AS claim as sameness, which is the
    `01 case 1` weld, and the offline seed is built from that output (C3).
13. `view:changed` no longer wakes a source blocked on a field that arrives inside an existing row, and
    `04 section 3` explicitly requires that check for `waitForMedia`'s seven callers (C4).
14. `Media._id` is no longer monotone (a `plugin:aggregate` version bump retracts every cluster id, and
    splits are now possible) and `Slot.id` embeds it, so `Episode._id` inherits both (C5, D6).
15. The aggregated uri can now shrink, and it is a bookmark, a route and a party-synced path (C6).
16. The core's runtime proof that a plugin left source rows alone is `max(seq), count(*)`, which cannot
    see a `SET` on an existing row, and the verb checker is a parser problem solved with a word list
    against an engine that accepts multi-statement queries (D2).
17. Nothing refuses a `PART_OF` proposal over a pair an active `SAME_AS` already joins, so the owner's
    containment rule can be broken by which plugin ran first (D3).
18. A plugin that throws mid-run is unspecified, and a pass that aborts before `view:changed` leaves a
    page empty forever (D4).
19. `store/consensus.test.ts` is counted as KEEP verbatim while `9.1` deletes three of its four
    subjects, so the 55/18/1 split is overstated and the two episode defects it pins lose their tests
    (E1).
20. Step 1 is not a day, and what it says it ships (the trace story) needs tables that do not exist
    until step 2 (F1, F2).
21. Step 3 leaves the listing on the fuzzy-merged old store and the detail page on the direct-only new
    one, so a card and the page it opens disagree about membership and `_id` (F4).

### Minor

1. Map projection `m {.prop}` is used in four load-bearing queries and is absent from `00`'s verified
   list (A3).
2. Filtered variable length paths are written without the bound rel variable `00` verified (A4).
3. The `7.5` path trace stacks four unverified features (named path over a filtered recursion,
   `rels(p)`, a struct-building comprehension, a rebound `r`) (A5).
4. `MERGE`'s all-or-nothing rule pins `CLAIMS.node` to the claimer's first, poorest description (A8).
5. `Answer.selection` cannot be derived from the result object the hook sees (B7).
6. Removing the singleton branch of `aggregateMedia` changes every single-source card's uri, origin and
   url, and the migration does not name it (C10).
7. A third `MediaHandleRelation` value is a client-visible schema change (C11).
8. The four-iteration cap means a read can render a non-fixed-point graph, which qualifies `G3` (D5).
9. `P3`'s year bucketing collects years only from profiles that already have title keys, where
   `profileCluster` collects years from every member and skips the cluster only when it has no titles
   at all (`fuzzy-merge.ts:597-605`), so a priced pass changes its input silently.
10. `9.3`'s closure cross-check is capped at 8 hops against an unbounded union-find (E2).
11. `store/edge-idempotence.test.ts` as rewritten no longer covers the write path (E5).
12. Step 6 bundles the `address` decision, which `11.2` says the owner must make, with the deletion of
    the old store (F6).
