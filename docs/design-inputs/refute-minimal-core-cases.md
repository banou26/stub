# Refutation of `proposal-minimal-core.md` through the edge case lens

Every numbered case of `01`, every refutation `R1` to `R26`, every invariant `I1` to `I15`, walked
against the proposal as written. Verdicts: **HOLDS** (the stated rule and the real rows produce the
right edge), **FIXABLE** (wrong or missing, repairable inside the design), **FATAL** (the design
cannot satisfy it without changing a principle or a worked example).

Two conventions used throughout:

- "the proposal's N" cites the proposal's own section numbers (2.1, 5.5 I5, 5.9, 8.1 and so on).
- A verdict is not granted for "a plugin would catch that". Each row names the table, the edge, the
  rule and the rows.

## Summary

### FATAL (cannot be satisfied without changing a principle or a worked example)

1. **C4, the count-exact fold, is incoherent as written and unsafe under its only working reading (case 9, `01 I6`, `01 I10`).** As specified it selects "a container cluster member that is a RUN-scoped season row", a set identity I4 guarantees is empty. Read charitably (a RUN-scoped season row `PART_OF` the same container), the proposal's own walkthrough is wrong: with cours 11, 12, 12, 12, 14 the contiguous pair sums are 23, 24, 24, 26, so JustWatch's season of 24 matches two windows and C4's "exactly one such window" must refuse the edge 8.1 claims it mints, while any relaxation that admits it also admits Netflix season 1 = 24 pointing at cours 2 and 3, rendered as a `PART_OF` handle with a playable Netflix url on two wrong run pages. Only the sums 23 and 26 are unique here, so the rule is inert where it is safe and wrong where it is useful. It is `R20`'s offset composition with counts as the lookup table.
2. **An accepted SAME_AS claim to an anchor with no payload disappears from the page (case 48, case 42, case 40).** `MEMBER_OF` is emitted only for anchors with a payload (5.5) and handle nodes never become payloads (4.2), while `Aggregate.handles` builds SAME_AS from members. Six origins exist solely to render such a handle (`03`: disney, amazon, hulu, peacock, hbo, fubo), and JustWatch's offer node carries a `url`, which today makes it a stored non-placeholder and therefore a member (`db.ts:104-108`, `justwatch/extractor.ts:399`, both confirmed in the tree). The PART_OF half of this is patched and the SAME_AS half is not, so film-level provider links and watchmode's provider handles vanish. `01 case 40` measured that class at 515 handles and 119 offers.
3. **The loan now requires dated episodes on the RUN side, which most runs do not have (case 12).** `plugin:range` is the only path by which a containing season reaches a run, and episode release dates are on the wire from anizip, crunchyroll, appletv and the seed only (`03 section 3`), with anizip answering only when the cluster carries a mal id. Today `runEpisodes`' `1..length` window lends the correct prefix with no date at all, which is how Mushoku season 1 cour 1 gets Crunchyroll's episodes 1 to 11 from a season of 23. The proposal deletes that path and calls it arithmetic placement, which it is not: the placement is the container's own numbering, trimmed by the run's own corroborated length.
4. **The episode window drops the spared sets, so an episode that aired is deleted (case 45, `01 I9`, `01 I11`).** `consensus.ts:210-211` spares `reference` and `equals` origins from the window and trims only a strictly lower tier; proposal 5.9 step 3 windows everything to `1..length`. With `anilist(0.8)=13` against `mal(0.9)=12` the thirteenth row goes, which is the exact outcome the twice-the-weight margin was measured to prevent.
5. **Case 23 is claimed and not delivered.** The zero-for-absent defect lives in seven source call sites reading `media.episodes.length` off an aggregate that always emits `[]`, and proposal 5.9 keeps `episodes` off the aggregate. No plugin can see a veto that fires inside a source.

### SERIOUS (wrong or missing, fixable inside the design)

- **I5's fold veto is inert on the clusters with the thinnest evidence** (`01 I9`): it needs "an agreed length backed by two declared counts", and Mushoku season 2 part 1 has one. The design leans on I5 for cases 9, 10 and 12.
- **I5's `C < L` demotion fires on every airing show** (case 10): a Crunchyroll row whose fetched list is short loses membership, and with it its cover, banner and description (0.5, above kitsu), for a whole broadcast season. The declared/derived distinction the rule needs is not on the wire (case 22).
- **I6 is promoted from a test-only report to a production veto with no measured arm, and arbitrates arbitrarily** (cases 11, 43, `01 R7`). Two runs of eleven episodes each contradicting over one Netflix season is settled by a sha-256 tie-break, so half the time the playable link lands on the wrong run; `mal:51535` on two AoT parts strips one part of the entire 0.9 tier, with the loser chosen by hash. `01 I2` says a wrong row is a lie, and an arbitrary winner mints one.
- **The declared/derived count class is a per-origin constant inside a plugin** (case 22), and it is wrong for kitsu (`attr.episodeCount` overwritten by the fetched list) and for justwatch (released count preferred over `totalEpisodeCount`), which is `01 case 44`'s mistake repeated.
- **A foreign `SOURCE` stamp outranks the anchor's own describing payload** in effective scope (I3), widening a rule the record narrowed after the seed overwrote a live row (`01 case 47`).
- **`attached` is global where `hideAttachedContainers` is per page** (case 49), so a container whose runs are filtered off the page loses its card.
- **A read now answers only after a completed pass** (proposal 6.2, 11.1). `waitForMedia` polls from inside a source resolver while the runner serialises every plugin, and case 12's "four defects only the running app showed" are all timing defects of exactly this shape. The proposal's mitigation ("the deadlines are unchanged") is not an argument about the new latency.

### MINOR

- Episode number spaces are not labelled (case 14); only the date axis saves it.
- `LINKS` granularity is mixed: 2.2 declares `FROM Media TO Media`, 3.2 and 8.1 mint media-level `INCLUDES`, 5.6 mints cluster-level, and 5.9's aggregate query collects only cluster-level `INCLUDES`, so lent episodes may not reach the slot at all as written.
- `VERDICT` is `FROM Payload TO Media`, but the identity scan also judges `LINKS` rows from `plugin:title`, which have no payload endpoint, so those verdicts cannot be written.
- I5 reads the inflated `episodeCount` while C4 reads distinct ids (case 16).
- `Cluster.aliases` is never retracted, so an old `_id` can resolve to the wrong cluster after a split (I1).
- The year set is not attributable to the payload that supplied it (case 3).
- No per-format date window (case 36); no title variant table (case 31); no `(origin, kind)` anchor key (case 39); `overLength` still has no runtime consumer (case 46).

### HOLDS (the hardest cases it clearly handles)

- **One chokepoint** (case 7): `MEMBER_OF` has exactly one producer and the runner enforces it.
- **The same evaluation path for an id claim and a title guess** (case 2): `plugin:title` emits `LINKS SAME_AS` and identity judges it with I4, I5 and I6, so a guard written once applies to both, and it is reachable from the direction the claim arrives in.
- **Nothing reached through `PART_OF` or `INCLUDES` is ever treated as `SAME_AS`** (proposal 3.4, cases 18, 51, `01 I10`): the filtered path cannot step onto another kind, and the episode walk is structurally forbidden from crossing a container, which retires `sameAsHandleUris`' "most dangerous read in the tree".
- **Reversibility** (`01 I1`): membership is recomputed per pass and every plugin row is retractable by its stamp.
- **The range form is the primitive the record asked for** (cases 13, 15, 51): explicit `fromEpisode/toEpisode/mapsFrom/mapsTo` with witnesses, piecewise segments, and no arithmetic past the last witness. Blue Exorcist mints nothing (`01 R1`), the Elusive Samurai's 13..20 maps to 1..8 (`01 case 13`).
- **The seed can no longer ratify itself** (case 47): `SEED` never stamps and the export walks `SOURCE` claims only.
- **The address-bar handle is a pointer** (case 8, `01 part 4 problem 2`).
- **Title matching is carried verbatim**: 0.9, the trailing-number value comparison, the six-title cap in title-ascending order, the both-sides normaliser, the day1 guard, the 45 day window, the companion veto's two signals (cases 24, 25, 26, 30, 33, 34, 36, `01 R4`, `01 R6`, `01 R17`).
- **No refuted approach is retried** except `R20` inside C4: no offset vote, no weighted sum, no silence veto, no threshold tuning, no Netflix title join, no mapping datasets.

**Score: 6 / 10.** The spine (one chokepoint, retractable verdicts, provenance on every claim, a closed edge set, ranges with witnesses, the traversal prohibition) is the right answer to the brief and to `01 I1`. The failures are concentrated in four places: one new rule that is either inert or mints a wrong playable link (C4), one omission that silently deletes a shipped feature (payload-less SAME_AS handles), one replacement that drops evidence today's code keeps (the count plus window loan, and the window's spared sets), and a set of new refusals whose exchange rates were never measured, which is the one habit `01 I2` says every rule in this repo has had to earn.
