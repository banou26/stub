## Summary

### Fatal

1. **The stated proof that a plugin never touched a source row is not a proof** (finding 10). `sum(size(a.hash))` is invariant under any content change at fixed hash length, the counts are invariant under an in place rewrite, and the check runs only in dev builds and tests. The facade is a string check over a dialect where `00` records that multi statement `query("...; ...")` works. Principle 2 says "the core proves it with a digest that must not move"; the digest as written cannot move for the mutation it is aimed at. The architecture is fine; the claim has to be replaced by a content sensitive, always on digest plus a parse level facade, and by resting on the applier being the only writer.
2. **`count-sum` plus 5.12 step 4 ships R1's outcome** (finding 11). The document says positional placement cannot be mistaken for per episode identity and then makes every positionally placed container episode a SAME_AS episode handle, which `04` section 2.3 turns into a playable url on the watch page. `01` R1 refused exactly this on live data, and the refutation it names (a one vote margin) is not the mechanism it is guarded against; an exact count sum does not exclude an intra season insert paired with a short season. This also breaks the document's own principle 6. One table row fixes it: a container episode may contribute a number through a range and may only become a SAME_AS handle where a `SAME_EPISODE` edge exists.

### Serious (wrong or missing, fixable inside the design)

- Scope defaults to null instead of RUN, so the derivation table has no matching row and `membership`'s `a.scope = b.scope` never matches for two silent rows (1).
- The `view` plugin is per cluster execution, 4,000 plus round trips on a cold load, against `00`'s 18x per row penalty and the document's own "forty statements per round" (6).
- The listing serializes every cluster's full aggregate on every event because filters stay in JS (7).
- No error policy for a plugin that throws, and the read path sits downstream of all fifteen (8).
- The 100 ms trailing debounce in front of the round starves `Subscription.media` and the seven `waitForMedia` callers, which have no debounce today (9).
- The `split` veto vetoes on any short count from any answer, against `02` section 2.9's twelve sources that publish `episodes.length` (12); the `fold` veto has the same unselected `COUNTED` pattern.
- A scope ratchet after a join leaves a cross scope `JOINS` with no retraction path, so the invariant that must "return 0 after every round" fails on the measured justwatch / crunchyroll race (13).
- Retraction changes `_id` and shrinks the aggregated `uri`, against `04` contracts 1 and 2 and `shouldGrowAddress` (14).
- The hash newness test fires on any byte change where today only a new row, union or edge fires (15).
- The export walks raw `CLAIMS` rather than the applied same scope pairs `ASSERTED_LABELS.RUN` records (16).
- `Answer.key`'s `kind` is the resolved field name, so documents sharing a field name collide, which is the truncation class 4.4 claims to close (17).
- One malformed row rejects the shared 250 row batch, the failure `04` section 4.3 already measured in production (19).
- Most plugin scans have no incremental filter, and `seq` exists for exactly that and is never used (20).
- `Facet` keyed on the shared normalized title loses the per raw ordinal `02` section 2.10 requires (21).
- `MEMBER_OF` uniqueness is assumed everywhere and enforced and checked nowhere (22).
- Plugin disagreement resolves by round order (23), and the veto / counts / membership cycle has no proven fixpoint across rounds (24).
- The plugin tests assert a digest that cannot fail (26).
